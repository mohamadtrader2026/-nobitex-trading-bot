# Nobitex Trading Bot

ربات معامله‌گر نوبیتکس برای بازارهای ریالی (IRT).

## انتخاب هوشمند بازار

ربات دیگر فقط روی BTC قفل نیست. در هر چرخه، چند بازار ریالی قابل‌پشتیبانی را از اردربوک عمومی نوبیتکس بررسی می‌کند و با ترکیب روند MA، مومنتوم، نقدشوندگی، فاصله خرید/فروش، درصد حرکت‌های صعودی و نوسان قیمت به بازارها امتیاز می‌دهد. بازار با اسپرد بالاتر از ۰٫۲۵٪، نوسان بالاتر از ۰٫۲۵٪ در هر نمونه، روند/مومنتوم منفی، حرکت صعودی ضعیف یا نسبت عمق سفارش‌های خرید کمتر از ۴۰٪ رد می‌شود. نسبت عمق اردربوک یک نشانه کوتاه‌مدت است و به‌تنهایی پیش‌بینی قابل اتکا نیست. اگر هیچ بازار شرایط را نداشته باشد، خرید انجام نمی‌شود. این فیلترها برای کاهش ورودهای ضعیف هستند، نه تضمین سود؛ قبل از استفاده واقعی باید با داده تاریخی و کارمزد واقعی بک‌تست شوند.

بازارهای قابل بررسی از این فهرست ترجیحی هستند و اگر نمادی در پاسخ نوبیتکس وجود نداشته باشد خودکار کنار گذاشته می‌شود: BTCIRT, ETHIRT, USDTIRT, DOGEIRT, XRPIRT, LTCIRT, ADAIRT, SOLIRT, TRXIRT, LINKIRT, XLMIRT.

مستندات رسمی نوبیتکس دریافت اردربوک همه بازارها را از GET /v3/orderbook/all و بدون توکن توضیح می‌دهد.

## وضعیت ایمنی فعلی

ربات به‌صورت پیش‌فرض در Testnet و TEST MODE اجرا می‌شود و سفارش واقعی ثبت نمی‌کند. اگر Testnet از محیط اجرا در دسترس نباشد، در TEST MODE فقط برای ادامه تست استراتژی از داده عمومی بازار اصلی استفاده می‌شود؛ این fallback به معنی معامله واقعی نیست.

برای حالت واقعی باید آگاهانه این موارد تنظیم شوند:
- NOBITEX_API_ENV=mainnet
- NOBITEX_TEST_MODE=false
- NOBITEX_API_TOKEN

توکن API را داخل کد یا GitHub commit قرار ندهید.

## بک‌تست آفلاین با کارمزد

برای سنجش استراتژی قبل از استفاده واقعی، فایل `backtest.py` دادهٔ تاریخی اردربوک را از CSV می‌خواند و با همان فیلتر انتخاب بازار، حد سود/ضرر و کارمزد تخمینی هر سمت معامله، گزارش می‌سازد. هیچ دادهٔ تاریخی ساختگی دانلود یا تولید نمی‌کند.

فرمت CSV (هر ردیف برای یک نماد در یک زمان؛ برای هر زمان چند نماد می‌تواند باشد):

```csv
timestamp,symbol,price,bid,ask,depth
2026-01-01T00:00:00Z,BTCIRT,100000000,99900000,100100000,50000000
```

اجرا:
```bash
python backtest.py history.csv --fee-pct 0.1 --output report.json
```

`--fee-pct 0.1` یعنی کارمزد تخمینی ۰٫۱٪ برای هر سمت معامله؛ مقدار واقعی را از کارمزد حساب خودتان تنظیم کنید. گزارش علاوه بر سود خالص، ضریب سود، امید ریاضی هر معامله، میانگین برد/باخت و بیشترین رشتهٔ باخت را هم ارائه می‌دهد. ترتیب زمان‌ها بر اساس UTC مرتب می‌شود و حد زیان روزانه مطابق پایهٔ ریسک پیکربندی‌شده اعمال می‌شود. قیمت خرید از ask و قیمت خروج از bid محاسبه می‌شود تا اسپرد لحاظ شود. داده باید واقعی و با فاصلهٔ نمونه‌برداری ثابت باشد. نتیجه به‌تنهایی تضمین سود آینده نیست؛ کیفیت داده، کارمزد، لغزش، حداقل سفارش و نرخ نمونه‌برداری روی نتیجه اثر دارند. موقعیت باز انتهای فایل به‌عنوان معاملهٔ بسته‌شده شمرده نمی‌شود.

## نکات مهم

- در هر لحظه فقط یک موقعیت باز نگه داشته می‌شود.
- وضعیت موقعیت و تاریخچه کوتاه قیمت‌ها در bot_state.json ذخیره می‌شود تا بین چرخه‌های GitHub Actions منتقل شود.
- حد ضرر پیش‌فرض ۱٪ و حد سود پیش‌فرض ۵٪ است. سقف زیان روزانه ثابت و برابر ۲۰۰٬۰۰۰ ریال زیان تحقق‌یافته است؛ پس از رسیدن شمارنده به این مقدار، ورودهای جدید تا روز UTC بعدی متوقف می‌شوند. این سقف درصدی از موجودی کل حساب نیست. زیان روزانه با کارمزد تخمینی هر سمت (پیش‌فرض ۰٫۱٪) محاسبه می‌شود و شمارنده بر اساس روز UTC ریست می‌شود؛ موقعیت باز همچنان با حد سود/ضرر مدیریت می‌شود. هیچ‌کدام تضمین سود یا جلوگیری از لغزش قیمت نیستند.
- قبل از معامله واقعی باید مدیریت timeout/reconciliation سفارش‌ها و اجرای همیشه‌روشن با دقت بیشتری بررسی شود.
- برداشت وجه نباید برای API Token فعال باشد.
- Codespaces و GitHub Actions اجرای دائمی 24/7 را تضمین نمی‌کنند.
